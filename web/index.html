The same camera, in a browser tab

This is the Android app rebuilt against the web camera stack. Same layout, same modes where the browser can back them up — and honest gaps where it cannot.

What works here

  • Night stacking. Captures N frames and averages them on a canvas. Random noise falls by roughly the square root of N, exactly as in the Android build.
  • Torch, zoom, grid, timer, mirroring. Torch and optical zoom use media track constraints when the device exposes them; otherwise zoom is a canvas crop.
  • Exposure compensation through exposureCompensation, where the browser implements it.
  • Burst writes a short series of frames.

What cannot work

  • RAW / DNG. No browser API exposes sensor data. Android build: yes.
  • Manual ISO and shutter speed. Only exposure compensation is standardised. Android build: yes.
  • HDR exposure bracketing. A browser cannot pin three different shutter speeds. Android build: yes.
  • Panorama with gyro. Needs device orientation at capture time. Android build: yes.
